# 单文件引擎 · 平台接入三步（C-2 / C-3 的交付物）

**日期：** 2026-10-27
**对象：** C（工程） + A0 提示词维护者
**上游依据：** `docs/integration/2026-10-27-给C-的合并指令-引擎判定接入.md`、`docs/review/2026-10-27-share运行诊断与差距判定.md`
**目的：** 让平台 Agent 的每一个 `verdict` 都来自沙箱里的引擎，而不是 LLM 口算。

---

## 0. 一句话

SciencePal 没有"上传源码"的入口，因为它交付的单位是 **Agent 配置（提示词 + 知识库 + 工具）**，不是仓库。
源码要生效，只有三条路：**沙箱里被执行**、**Skill 包里被携带**、**外部服务被调用**。
本文件交付前两条路需要的那个"单文件"。

---

## 1. 交付物

| 文件 | 作用 |
|---|---|
| `skills/chemcritic-comparability/scripts/chemcritic_engine.py` | 单文件自包含引擎（67 KB，纯 stdlib，内嵌 8 条 L2 记录） |
| `skills/chemcritic-comparability/scripts/examples/user_35pct.json` | 演示输入（35% 分离收率案例） |
| `skills/chemcritic-comparability/SKILL.md` | v0.2.0：加了执行命令、输入/输出契约、`未拿到脚本输出不得给 verdict` 纪律 |
| `engine/build_bundle.py` | 生成器：`engine/*.py` + `data/records.json` → 单文件；`--check` 校验产物是否同步 |

**已验证（本机）：**

```text
python engine/build_bundle.py --check          → 产物与源文件一致
python scripts/chemcritic_engine.py --selftest → 最终：19 passed, 0 failed
python scripts/chemcritic_engine.py --json     → 与 engine/run_demo.py --json 输出 JSON 相等
--input examples/user_35pct.json               → SM-001b COMPARABLE 40%，delta_vs_min = -5.0，tier A
```

## 2. 三步接入

### 第 1 步 · 让文件在沙箱里可见（10 分钟）

先确认平台给不给沙箱持久工作区——这是 10/25 计划里那张平台验证卡的第一项。在沙箱里跑：

```bash
pwd && ls -a && python -V && python -c "print('sandbox ok')"
```

| 结果 | 走哪条路 |
|---|---|
| 有可写工作区、能上传/保留文件 | **A 路**：把 `scripts/chemcritic_engine.py` 放到工作区（如 `./chemcritic/`），全程用它 |
| 只能执行代码字符串、无文件系统 | **B 路**：Skill 包（平台若支持 `SKILL.md + scripts/`）带上脚本；否则走第 4 节降级 |
| 连 Python 都没有 | 直接降级，别在演示前折腾 |

### 第 2 步 · 让 Agent 按固定顺序调用（15 分钟）

给 A0 的提示词加一段（可直接粘，放在"第三步 · 8 维门槛"之前）：

```text
# 判定必须来自引擎（不得口算）

每次需要给可比性结论时，按顺序执行，不得跳步：

1. 把用户实验整理成 Record JSON，字段缺失写 null，写到 `user.json`；
2. 运行：`python chemcritic_engine.py --json --input user.json`
3. 把输出的 `verdicts[]` 原样当作结论来源：`verdict` / `blocking_dimension` /
   `unlock_condition` / `calibration` 一个字都不许改；你只负责把它翻译成用户能懂的话。

硬约束：
- 没有第 2 步的输出 → 不许输出任何 verdict，只能回答"本次未执行判定（引擎不可用）"。
- 脚本报错/超时 → 重试一次；仍失败则明确告知"判定未执行"，不得用记忆补结论。
- 首次使用前先跑 `--selftest`，必须看到 `19 passed, 0 failed`，把该行贴进会话作为引擎就绪凭证。
```

### 第 3 步 · 验收（20 分钟，缺一不可）

| # | 验收项 | 合格信号 | 不合格说明 |
|---|---|---|---|
| 1 | 引擎在沙箱可执行 | `--selftest` 打印 `最终：19 passed, 0 failed` | 路径/依赖问题；`chemcritic_engine.py` 无第三方依赖，只可能是 Python 版本或文件没落地 |
| 2 | 判定真的走引擎 | 同一 35% 案例重跑，会话里出现证书 JSON，`SM-001b` 为 `COMPARABLE`、`calibration=calibrated`、`delta_vs_min=-5.0` | 说明提示词没被执行，Agent 仍在口算 → 回到第 2 步加强硬约束 |
| 3 | unknown 判对 | `SM-004.1/7` 必须是 `NEEDS_EVIDENCE`（阻断维度 `outcome_type`），不是 `COMPARABLE`，也不是"不能比较" | 踩 10/27 诊断里的问题 2 |
| 4 | 无库外引用 | 会话里没有任何 `records.json` 之外的作者/数值 | 检查第 5 步（联网）是否关掉 |
| 5 | Skill 能被检索 | `search_skills("chemcritic")` 命中 `chemcritic-comparability` | 未注册；只靠提示词扮演角色 = 诊断里的硬伤 1 |

截图与证书 JSON 存 `outputs/`，按合并指令 §7 写 `docs/integration/2026-10-27-live-002-验收结果.md`。

## 3. 沙箱里跑不通时的降级（不需要平台支持）

本地或任意环境跑引擎，把**证书摘要**贴回会话，由 Agent 翻译：

```bash
python chemcritic_engine.py --brief --input user.json
```

输出约 700 字节（`verdicts[]` 只留 `ref/v/block/calib`），足以支撑一次完整复盘卡片，且**来源可指认**。
材料里如实写："判定在本地引擎执行，平台负责检索与编排"——赛题允许透明披露，禁止的是伪称。

---

## 4. 已知边界（写进说明里，别在评审时被问倒）

1. **Skill 是否携带 `scripts/`** 取决于平台实现；若不携带，Skill 只是"规则说明书"，脚本仍需靠沙箱文件或本地执行。
2. **单文件内嵌的是 8 条已核验记录的快照**；新增记录后要重跑 `python engine/build_bundle.py`，否则沙箱与仓库会分叉。`--records` 可在运行时替换参照集。
3. **底物/产物比对目前是名称规范化**，不是 canonical SMILES；规则表 §2.1 已标注。换 name 写法（大小写/空格除外）会被判"不同底物"，属已知限制，不属 bug。
4. **`uncalibrated` 参照只展示**，不参与差值结论（`placement.uncalibrated_refs` 单独列出）。

## 5. 与既有文档的关系

- 判定语义的**唯一权威**仍是 `engine/gates.py`；本单文件是它的构建产物。
- 调用契约（输入字段、输出证书）见合并指令 §2；本文件只补"怎么放进去、怎么证明它跑过"。
- 修改顺序：改 `engine/*.py` → 跑 `python engine/run_demo.py`（19 passed）→ 跑 `python engine/build_bundle.py` → 跑 `--selftest` 与 `--json` 对比 → 再上传。
