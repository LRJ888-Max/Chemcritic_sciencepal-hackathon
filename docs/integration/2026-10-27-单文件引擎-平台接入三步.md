## 0. 一句话

平台的沙箱每个新对话都是空容器，所以**不能靠上传**：用一条自举命令把引擎装到固定路径，之后所有调用都指向这个路径，不再现场找、不再试错。

固定路径（自举后保证存在）：

```text
/workspace/chemcritic/chemcritic_engine.py      # 引擎
/workspace/skills/chemcritic-comparability/     # Skill（供技能检索）
```

---

## 1. 交付物

| 文件 | 作用 |
|---|---|
| `bootstrap.sh`（仓库根） | 一条命令：clone → 装到固定路径 → 注册 Skill → 自检 → 打印 `ENGINE_READY` |
| `skills/chemcritic-comparability/scripts/chemcritic_engine.py` | 单文件引擎（70 KB，纯 stdlib，内嵌 8 条 L2 记录，证书自带 citation） |
| `skills/chemcritic-comparability/SKILL.md` | v0.2.0：固定路径命令、输入/输出契约、禁术语泄漏 |
| `engine/build_bundle.py` | 生成器（`--check` 校验产物与源码同步） |
| `rebuild.bat` | 本地一键：打包 → 校验 → 19 项自检，**push 前必跑** |

---

## 2. 接入：三条命令解决

### 第 1 步 · 开场自举（新对话第一条消息，写在提示词最前面）

```text
# 开场自举（每个新对话执行一次；成功后可跳过）

cd /workspace && rm -rf .cc_src && git clone --depth 1 https://github.com/LRJ888-Max/Chemcritic_sciencepal-hackathon.git .cc_src && bash .cc_src/bootstrap.sh

看到 "ENGINE_READY /workspace/chemcritic/chemcritic_engine.py" 才算就绪；失败就说明"引擎未就绪"，不给任何可比性结论。
```

### 第 2 步 · 判定命令（写死在提示词里，不用 Agent 自己拼路径）

```text
python /workspace/chemcritic/chemcritic_engine.py --json --input /workspace/user.json
```

- 引擎返回的 `verdict / blocking_dimension / calibration / reference` 原样使用，不得改写；
- 引用直接取 `reference.citation` 与 `reference.locator`，**不要回头翻数据文件**（第 2 次诊断里这里烧掉了 9 次调用）；
- 没跑引擎 → 只能回答"本次未执行判定"。

### 第 3 步 · 输出纪律

按 [`提示词补丁 v3.1`](2026-10-27-提示词补丁v3.1-演示观感.md) 整段追加：答案只交付一次、不输出过程自述、不出现 `L1/L2/record_id/引擎/19 passed`。

## 3. 验收（5 项，缺一不可）

| # | 项 | 合格信号 |
|---|---|---|
| 1 | 自举 | 首条命令就打印 `ENGINE_READY`，无路径试错 |
| 2 | 判定走引擎 | 会话里能看到引擎返回，`SM-001b` COMPARABLE、`calibration=calibrated`、`delta_vs_min=-5.0` |
| 3 | unknown 判对 | `SM-004.1/4.7` → NEEDS_EVIDENCE，文案"需先确认原口径" |
| 4 | 引用可核验 | 全部来自证书 `reference.citation`，无库外文献 |
| 5 | 回放观感 | 只有一条最终答案；无英文过程句；`L1/L2/record_id` 0 命中；工具调用 ≤10 次 |

## 4. 降级（沙箱不可用时）

```bash
python chemcritic_engine.py --brief --input user.json
```

输出约 2 KB，每条 verdict 带 `cit` / `loc`，可直接贴回会话；材料里如实写"判定在本地引擎执行，平台负责检索与编排"。

---

## 5. 维护（改引擎之后）

**顺序固定，别跳步：**

```bat
rebuild.bat
```

它依次做：`build_bundle.py`（把 `engine/*.py` + `data/records.json` 重新打包）→ `--check`（产物与源码一致）→ `--selftest`（19 passed）。

通过后再 `git add / commit / push`。**没 push 等于没改**——沙箱每个新对话都从 GitHub 拉，拉的是仓库里的旧版。

---

## 6. 已知边界

1. 仓库必须 **Public**，否则沙箱不带 token 拉不到；**绝不要把 token 写进提示词**（share link 会暴露提示词原文）。
2. 单文件内嵌的是 8 条已核验记录的快照；新增记录后必须 `rebuild.bat` 再 push，否则沙箱与仓库分叉。
3. 底物/产物比对仍是名称规范化，不是 canonical SMILES；换写法会被判"不同底物"，属已知限制。
4. Skill 是否能被 `search_skills` 命中取决于平台加载路径（`/workspace/skills/`）；自举会往那里放一份，失败只告警不阻断。
