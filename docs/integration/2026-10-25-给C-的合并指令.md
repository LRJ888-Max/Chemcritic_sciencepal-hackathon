# 给 C 的合并指令：把 `engine/` 接进 `test_code/`

**日期：** 2026-10-25
**发起：** A（队长）／技术侧
**对象：** C（工程）
**原则：** **以你的 `test_code/` 为主体，`engine/` 只提供判定内核。不需要重写 app，不需要改你的 UI 结构。**

---

## 0. 为什么要合并

仓库里现在有两套判定，结论互相矛盾：

| | 你的 `test_code/`（`core-0.2.1-partial`） | `engine/`（`tier-0.1` + 8 维门槛） |
|---|---|---|
| 同口径文献数值 | **关闭**（`mvp_numeric_disabled`） | **允许**（同口径 + 同档 + 过硬门槛） |
| 能否说"你的 35% 属于档 A，该档参照 40%" | ❌ 不能 | ✅ 能 |
| 档位判定 | 无 | 受控词表 → 规则 → 边界敏感性 |

**问题：** 如果照现状交，Demo 会演成"文献数值一律不能比"，而项目说明写的是"能在同口径同档内比"——评委一问就穿。

**裁决：** 保留你已实现的全部工程资产，只替换**判定语义那一个分支**。

## 2. 第二步：改 `rules.py` 的判定分支（核心改动）

现在的位置：`app/chemcritic/rules.py:228-232`，同口径时走

```python
reason = "mvp_numeric_disabled"
```

**改成调用引擎**。在 `rules.py` 顶部加：

```python
from .engine.adapter import from_library
from .engine.gates import judge
from .engine.tier import tier_of
```

新增一个函数，替换原分支：

```python
def compare_with_library(user_record, library_records):
    """返回逐条 Verdict；COMPARABLE 才允许进入数值比较。"""
    verdicts = []
    for raw in library_records:
        ref = from_library(raw)                      # 你的 JSON → 引擎 Record
        ref.tier = tier_of(ref.catalytic_profile)["tier"]   # 档位由规则算，不读标注
        verdicts.append(judge(user_record, ref))
    return verdicts
```

**必须保留的原有行为**（这些是对的，别动）：

- `assay_mismatch`（口径不同）→ 继续阻断
- `assay_unknown`（口径未知）→ 继续阻断
- `user_report` 不升级为已核验产物
- 追问、逐字段"相同/不同/未知"、证据分层、`base_status` 三态、`simulated` 标记

**必须撤掉的只有一条**：同口径也禁止比较（`mvp_numeric_disabled`）。

## 5. 第五步：SciencePal 从"贴文件"升级为"知识库检索"（最关键）

现在：`retrieval.mode = "sciencepal_file_import"`，`live_retrieval_performed = false`。
目标：`"knowledge_base"` + `true` + 可点开的会话链接。

### 5.1 平台侧（不用写代码，20 分钟）

1. 在 SciencePal 的 **Personal Knowledge Base** 上传 11 篇 PDF（`outputs/2026-10-21-Suzuki文献包/PDF/`）
2. 在会话里问：`4-溴苯甲醚 + 苯硼酸 Suzuki 偶联的收率，按表逐条列出，给出表号与脚注`
3. 确认返回里有**表号 / entry / 脚注**，而不只是论文标题
4. 生成 **share link**

### 5.2 应用侧（约 100 行）

把 `sciencepal.py` 的输入从"粘贴 JSON"改为"检索结果导入"，输出契约：

```json
"retrieval": {
  "mode": "knowledge_base",
  "live_retrieval_performed": true,
  "queries": ["4-bromoanisole phenylboronic acid Suzuki yield"],
  "hits": [
    {"record_id": "SM-001", "locator": "Table II, p-MeOPhBr row, footnote",
     "snippet": "66% GLC; (40) isolated", "matched_library": true}
  ],
  "unmatched_hits": [],
  "session_url": "https://sciencepal.ai/share/xxxx"
}
```

**三条硬规则：**

1. `locator` **必须来自检索返回**，不许手填；对不上 library 的进 `unmatched_hits`，不静默丢弃。
2. 自报的 `tools_used` / `access_status` **不升级为已核验事实**（你现在这一点做得对，保持）。
3. 无命中时 `live_retrieval_performed` 仍为 `true`，但 `hits=[]`，并在 UI 显式显示"本次检索无命中"——**不能显示成"证据不足"就完事**，否则评审看不出到底有没有检索。
