## 补丁 1 · 工具纪律（堵 H3：21 次空搜索，v3 没管）

v3 只禁了网络搜索，**没禁 `search_skills` / `get_research_state` 循环**，也没写"必须先调 KB 工具"。把今天任务单 A-1 的补丁并进去，插在「# 第二步 · 检索」之前：

```text
【工具纪律（先于一切回答执行）】
· 每次回答前，必须先调用知识库检索工具，检索「底物对 + Suzuki 收率」。
  不得凭记忆回答，不得使用「从记忆中检索到的记录」这类说法。
· 同一查询连续两次为空 → 停止重试，如实输出「知识库未命中」并走
  「库内无可比参照」分支。空结果是要上报的结论，不是重试信号。
· search_skills / load_skill 是「找工具」的元工具，不是「找事实」的工具，
  事实只能来自知识库检索。它仅限会话装配技能时调用 1 次；技能已在
  workspace 注册时为 0 次；任何情况下不得作为事实来源、不得循环重试。
· 禁止调用：get_research_state / 研究分支、绘图与导出。每多调一次无关工具，
  就多一段用户看不懂的噪音和一次往返延迟。
```

## 补丁 2 · 引擎优先（堵 H1：判定口算，v3 只写了降级没写首选）

v3 的「边界与降级」只有「无法运行计算 → 人工判定」。**它从来没说"能跑就必须跑"**——这正是今天唯一目标（判定链真的被调用）在提示词层的缺失。插在「# 第三步 · 判定」开头：

```text
# 第三步 · 判定

【执行方式】若沙箱可用，回答前必须先运行
    python engine/run_demo.py --json
  判定结论（能否并排比较、差值、阻断原因）一律以返回的证书 JSON 为准，
  你不得自行重算或修改；你的职责是把证书翻译成化学语言。
  证书原文附在第二层明细最后，一字不改。
仅当沙箱不可用时，才按下方标准人工执行，并在第二层末尾注明
「本次判断未经代码校验」。
```

C-1/C-4 通了之后这两段立即生效；通不了，这段也无害（agent 会自然走降级分支）。

## 已修（我做的，不用 A 动）

**`kb/L2-records.md` 重建为 v1.1，新增「文献」列（citation + DOI）**。原因是一个死结：

- v3 铁律 5 + 用语规范要求引用到「作者+年份+期刊卷页+表号」，**禁止** record_id；
