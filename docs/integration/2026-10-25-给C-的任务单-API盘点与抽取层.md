## 任务一 · 20 分钟：盘清 API 到底暴露了什么

**为什么必须先做：** "能调 API" 不等于 "能调全部能力"。如果 API 不暴露代码执行，我们的 8 维门槛就没法由外部指定运行，整个编排必须留在平台内——这直接决定架构。

### 检查清单（登录后在产品里逐项找，每项只记"有 / 没有 / 不清楚"）

| # | 查什么 | 在哪找 | 记下来用于判断 |
|---|---|---|---|
| 1 | **任务/会话接口**（发 prompt、拿结果） | 设置 → API / 开放平台 | 没有 → 整个 API 路线作废 |
| 2 | **代码执行接口**（能否让平台沙箱跑指定脚本） | API 文档的 tools / functions 列表 | **没有 → 编排必须留在平台内** |
| 3 | **知识库检索接口** | API 文档 | 没有 → 检索只能由平台 Agent 做 |
| 4 | **文件上传接口** | API 文档 | 没有 → 新文献只能手工传 |
| 5 | **异步任务查询**（长任务轮询） | API 文档 | 没有 → 只适合短任务 |
| 6 | **鉴权方式 + 配额/计费** | 设置页 | 演示时会不会烧完 |

### 决策树

```text
1 有？
├─ 否 → 只走平台内建 Agent（路线 A），app 仅作本地可复现材料
└─ 是 → 2 有？
    ├─ 是 → 可以走双路线：app 调平台跑 gates.py（控制力最强）
    └─ 否 → 编排必须留在平台内；app 只是"远端调用入口"
```

### 交付
一页纸：6 项结论 + 走哪条决策分支 + **截图**（证明看过，不是猜的）。

## 任务二 · 2 小时：把表格抽取跑起来

### 装在哪（重要）

**装在 SciencePal 沙箱里，不要装在仓库或本地环境。**

```powershell
# 沙箱内
pip install pdfplumber     # 先装这个（轻，几 MB），跑通了再考虑 Docling
```

**Docling 只在确认沙箱扛得住时再装**（`pip install docling` 会拖 ~2 GB 的 torch）。本地我试过 `pip install pdfplumber`，在代理下卡了 10 分钟没动静——所以本地不要折腾，沙箱是它该待的地方。

### 跑什么

代码已经写好，在仓库里：`engine/extract.py`

```powershell
# 单篇
python engine/extract.py <pdf路径> --json

# 指定页
python engine/extract.py <pdf路径> --pages 3,4 --json
```

### 用哪两篇做验收（都在 `outputs/2026-10-21-Suzuki文献包/PDF/`，该目录不入 git，从共享包拿）

| 文件 | 为什么要它 |
|---|---|
| `SM-001_Miyaura1981_HUSCAP.pdf` | 目标记录 SM-001，表 II 有 `66% GLC/GC；40% isolated` 这种**一行两口径**，最考验抽取 |
| `02_Molecules2018_Pd-bpydc_直接底物.pdf` | 目标记录 SM-004，表 1 里 `35.0` / `91.9` **不带 % 号**（`Yield (%)` 只在表头）——这是**回归项**，第一版抽取器就是在这里漏的 |

### 验收标准（四条，缺一不可）

| # | 标准 | 怎么验 |
|---|---|---|
| 1 | 两篇都跑出非空 `candidates` | 看 `--json` 输出 |
| 2 | **每条的 `locator` 能真的翻到那一行** | 你按 `p.X table#Y rowZ` 去 PDF 里找一次，找得到才算 |
| 3 | **SM-004 的 35.0 和 91.9 必须出现在候选里**，且带 `extraction_note` | 这是回归项，漏了就是没修好 |
| 4 | 每条候选的 `outcome_type` 都是 `unknown`、`evidence_grade` 都是 `imported_unchecked`、`needs_confirmation=true` | 抽取器**不许替人判断口径** |

### 交付物（三样）

1. `outputs/extraction/<source_id>.json` —— 每篇一份，原样输出
2. **一张确认表**（渲染成网页或 CSV 都行），每行四列：

   ```text
   locator | 原文这一行 | 口径（isolated/GC/NMR/conversion/unknown） | 内标或基准
   ```

   表里"口径"和"内标"两列**留空**，等 A 填。这就是"不再让人翻 PDF 找表"的落地形态。
3. 一段话说明：用了哪个后端、耗时、失败的行怎么处理的

### 四条禁区

| 禁区 | 原因 |
|---|---|
| ❌ 不要让抽取器**猜口径**（把 `35.0` 自动判成 GC 收益） | 口径判断是产品核心，必须由规则或人确认；猜一次，整套"不许假精确"就废了 |
| ❌ 不要 OCR 猜图片表格 | 抽不出就标 `needs_manual_check`，不猜 |
| ❌ 不要把结果直接写进 `data/records.json` | 必须等 A 确认后再入库，否则等于绕过核验 |
| ❌ 不要在候选里补默认值（如默认 temperature=25） | 原文没有就留 null，缺字段本身是信息 |

### 时间盒与降级

```text
00:00–00:20  装 pdfplumber，跑 SM-001
00:20–00:50  跑 02_Molecules2018，确认 35.0/91.9 在候选里
00:50–01:20  渲染确认表
01:20–01:40  按 locator 人工回查两条，验证 locator 可用
01:40–02:00  写说明 + 提交
```

**超过 2 小时没跑通 → 立刻停，改交付"确认表模板 + 手工填的 3 行"，并在说明里写"抽取层未打通，已降级为人工录入"。** 不要为了一个工具拖住主链路。
