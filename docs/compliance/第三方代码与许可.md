## 2. 计划/可能引用的开源项目

| 项目 | 许可 | 用途 | 我们要做什么 |
|---|---|---|---|
| [pdfplumber](https://github.com/jsvine/pdfplumber) | **MIT** | PDF 表格抽取（轻量后端） | 保留版权与许可声明；不改源码 |
| [Docling](https://github.com/docling-project/docling)（IBM） | **MIT** | PDF → 结构化（表格结构识别，首选后端） | 同上；仅调用其 API |
| [GROBID](https://github.com/grobidOrg/grobid) | **Apache-2.0** | 学术 PDF → TEI XML（备用） | 若使用：保留 LICENSE 与 NOTICE；标注未修改 |
| [RxnScribe](https://github.com/thomas0809/RxnScribe) | **MIT** | 反应式图解析（**未采用**） | 仅评估，未引入代码 |

### 许可义务要点

| 许可 | 义务 | 我们的处理 |
|---|---|---|
| **MIT** | 保留原始版权声明与许可全文 | 在 `THIRD_PARTY_NOTICES.md` 列出，并保留其 LICENSE |
| **Apache-2.0** | 保留 LICENSE + NOTICE；**修改过的文件必须标注** | 若引入 GROBID，仅作为独立服务调用，不改源码 |
| **不能用** | GPL / AGPL 类 copyleft 库（若分发闭源或有限公开） | 引入前逐个检查 `license` 字段 |

**结论：上述 MIT / Apache-2.0 项目都可以在比赛中使用**，前提是：① 保留许可声明；② 在资源使用声明中写清"用了哪个项目、用来做什么、有没有改"；③ **不把别人的代码说成自己的**。

## 3. 论文与数据：这里的风险比代码更大

| 类型 | 能否上传到平台 | 注意 |
|---|---|---|
| **CC BY**（如本文核验的多篇） | ✅ 可以，需注明出处 | 最宽松 |
| **CC BY-NC-ND** | ⚠️ 可分发原文，**不得修改/演绎** | 不要做改编版上传 |
| **CC BY-NC-SA** | ⚠️ 非商业 + 相同方式共享 | 谨慎 |
| **订阅/付费墙** | ❌ **不上传全文** | 只放 DOI 与官方入口 |

**我们的做法：**

- 仓库 `.gitignore` 排除 `refs/` 与 `outputs/` 下的 PDF，**不随代码分发**
- 知识库上传前逐篇记录 `license` 与 `redistributable` 字段（见 `kb/schema.json`）
- 缺 SI 的条目显式标注"未存档，仅提供官方入口"，不用非官方镜像替代

## 4. 赛题对"使用外部工具"的要求（原文要点）

来自 [Hackathon 提交清单](https://sciencepal.ai/hackathon)：

> **04 原创性与资源使用声明** —— 说明使用的模型、数据、代码、API 及外部工具；**区分赛前已有成果与赛事期间新增成果**；并简述团队分工及原创性、合规情况。

因此声明必须包含：

1. **模型**：SciencePal 平台提供的模型/Agent 能力；若使用其它模型，逐个列出
2. **数据**：公开文献（含 DOI 与许可状态）；团队自建的结构化记录
3. **代码**：本项目原创部分 + 第三方库（名称、版本、许可）
4. **API / 外部工具**：SciencePal 的平台能力（知识库/沙箱/分享链接）；PDF 解析工具
5. **赛前 vs 赛期**：
   - **赛前**：文献核验记录（10/18–10/21）、候选池、科学边界文档
   - **赛期**：8 维门槛规则与实现、档位判定、多智能体架构、知识库结构、评测设计
6. **团队分工**：A（化学与裁决）/ B（评测与标注）/ C（工程与平台）

## 5. 一个必须守住的红线

赛题写明：**"至少一个核心环节实质性使用 SciencePal"**，且"仅用于撰写介绍、润色文案或制作 PPT，不构成有效使用"。

**风险场景：** 如果 PDF 抽取用 Docling、判定用我们自己的代码、只有检索用 SciencePal —— 有可能被判"SciencePal 只在外围"。

**对策（已经写进架构）：** 让 SciencePal 承担 **三个**核心环节，而不只是一个：

| 环节 | SciencePal 能力 |
|---|---|
| 证据检索 | Personal Knowledge Base（带 locator 引用） |
| 判定执行 | Isolated Sandbox 跑 `engine/run_demo.py`（确定性规则） |
| 流程编排 | Agent Co-Building（六步链）+ Share Link（评审入口） |

**抽取工具只是"把 PDF 变成表格"的机械步骤，不承担判定，也不承担检索。** 这个分工在材料里要写清楚，否则容易被误判为核心环节被外部工具替代。
