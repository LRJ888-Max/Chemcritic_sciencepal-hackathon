# 功能拓展开发单 v2（双轨）：对照材料学智能体，追什么、怎么追

*ChemCritic ｜ 2026-10-30 ｜ v2 依据决策：提示词每次对话从 GitHub 重新 bootstrap，
**推上仓库 = 即时上线**，因此执行轴不必全面认输——用开源公共库组件接出「轻执行」能力。
*依据《2026-10-29-与材料学智能体对比-定位差异与深度评估.md》*
*提交截止 10-31，本单按「今晚能落地 / 明天能落地 / 只放 roadmap」分三档。*

## 0 · 双轨战略（v2）

- **Track A（判定轴，原计划）**：修精确度 + 三个判定新功能。这是主战场，先保。
- **Track B（轻执行轴，v2 新增）**：不跑 DFT，但用**开源公共库组件**（RDKit 等，
  沙箱 pip 可装、bootstrap.sh 接入）给引擎补上对方有、我们缺的「计算的手」——
  化学感知、衡算、统计。每一项都服务判定（让门槛更准、让覆盖更宽），不偏离红线。
- **仍然不做的**：DFT/MD、谱图解析、OPTIMADE 联库——这不是「有我就行」，
  是工作量与可信度问题：一天内接上的 DFT 是假的，评委问一句收敛参数就穿帮。
  轻执行不同：RDKit 的描述子、t 分布置信区间是货真价实的计算，经得起追问。

> 「参考公共库」的口径：对方的工具链全部是开源公共库（pymatgen / ASE / OPTIMADE /
> jobflow），我们也一样——不抄平台界面，抄开源组件。公共智能体库需要登录，无法匿名
> 抓取；除材料学智能体六项能力（截图核对）外的样本，需人工提供截图后再评估。

## 3 · P1：判定轴三个新功能（明天一天可完成）

### ① 文献—文献判定（`--judge-pair`）✅ 已实现（2026-10-30 凌晨，本机验证）

- **是什么**：用户给两条文献记录（或贴两段原文数值），引擎输出与用户判定同一张证书。
  回答的是综述/评审里最常见的问题：「这两个数能不能放进同一句话/同一张表」。
- **实现**：`chemcritic_engine.py --judge-pair ID_A ID_B`，复用 `gates.judge()` 零新增判定逻辑，
  输出双向证书（forward/reverse，两向不一致时对外取较严者）。
- **实测**：SM-001a vs SM-001b → BLOCKED/口径 + non_independent=true ✓；
  P20 vs P36（同口径不同底物）→ BLOCKED/底物 ✓；未知 ID → exit 2 干净报错 ✓。
- **叙事价值**：直接回应对方「03 跨数据库材料证据」——它解释计算值差异，我们隔离测量口径差。
  对外一句话：**「我们判定的是实验数值的可并排性，这是写综述和审稿的真实动作。」**

### ② 整表审计（`--audit-table`）✅ 已实现（2026-10-30 凌晨，本机验证）

- **是什么**：用户贴一张文献结果表（多底物 × 多条件 × 数值），引擎逐行跑判定，
  输出「哪几行能同框、哪几行卡在哪一维、每行对库有几个可比值」。
- **实现**：`chemcritic_engine.py --audit-table table.json`；接受 extract.py 候选行
  （values_found/row_raw 自动归一为 unknown 口径 + imported_unchecked）或完整记录行；
  演示输入见 `tests/fixtures/audit_table_demo.json`。
- **实测**：3 行演示表 → 表内 3 对（1 BLOCKED 口径 + 2 NEEDS_EVIDENCE），
  isolated 行对库 6 个可比值、gc 行 4 个、unknown 候选行 0 个——分层正确。
- **叙事价值**：对应对方「04 批量工作流」的判定版——批量不是跑任务，是批量拦截。

### ③ PDF 取证端到端验收（补上对比文档自己承认的短板）

- 对比文档 §8 原话：「对 PDF 知识库的自主检索尚未端到端验收」——这是评委一眼能戳的洞。
- 动作：refs/ 下任选一篇 PDF，跑 extract → 候选 JSON（imported_unchecked + label_raw）→
  人工确认一条入 records.json（evidence_grade 升 A_confirmed，全链留痕）→ 判定生效。
- 产出：一段 3 分钟录屏或 README 流程图 + 前后各一条记录 diff。
- **顺带涨覆盖广度**：广度 2/10 的瓶颈不是引擎是参照集；每确认一条新底物记录，
  判定广度直接涨。今晚起每确认一条都是净收益。

### ④ 能力边界自述（`--coverage`，半天，可砍）

- 引擎自己输出覆盖矩阵：底物 × 口径 × 档位，各格有几条 A_confirmed 参照。
- 用途：把「我们窄」变成「我们知道自己窄到哪一格，且每格可数」。
  评委问「覆盖多少」时，答案不再是道歉而是一张矩阵。
- 若时间不够：把 corpus_leverage 现有输出改个标题当 coverage 用，零开发。

## 3.5 · Track B：轻执行模块（v2 新增，明天可选 2 项）

> 共同形态：独立模块（`engine/chemsense.py` 等）+ CLI 子命令 + bootstrap.sh 加一行
> `pip install rdkit`（若沙箱装不动则模块自动降级为规则表，接口不变——先写降级路径）。

### B1 化学感知层（`--chemsense`，首选）

- **是什么**：底物结构（SMILES）→ 计算描述子：芳卤电子类（EDG/EWG）、邻位取代
  （空间位阻）、杂环类型 → 写进 placement 的 same_class 判据。
- **追什么**：直接根治「参照池污染」类问题——现在 same_class 靠底物名白名单，
  RDKit 后变成**算出来的化学分类**，换底物不用改代码。这是对方没有的判定轴增强。
- **成本**：半天。RDKit 描述子是标准计算，可核验、可答辩。

### B2 衡算与原子经济（`--balance`）

- **是什么**：用户配方 → 限量试剂判定、当量核算、原子经济性、理论收率上限。
  纯确定性计算，与判定结果并列展示（不参与 verdict）。
- **追什么**：对应对方「05 实验数据分析」的轻量版。成本 2–3 小时。

### B3 重复实验统计（`--replicates`）

- **是什么**：用户给 n 次同口径重复测量 → 均值、样本标准差、t 分布置信区间。
  **同口径内**的区间不违反铁律 4（禁的是跨定义合成区间）。
- **追什么**：让「差 Z 个百分点」带上不确定度，精确度直接上一个档次。
  成本 3 小时。注意：n<3 不给区间，只给均值。

### B4 条件指纹（`--fingerprint`，可砍）

- **是什么**：条件向量归一化哈希 → 秒查「完全相同/近似相同条件」的历史记录。
  成本 2 小时；演示观感好（" twin condition" 一键命中），价值中等。

**取舍**：明天最多选 2 项，首选 B1 + B3（一个治准、一个治精度）；B2 作为时间富余的备选。

## 4 · 只放 roadmap（答辩一句话，不实现）

- **新反应类型**（Buchwald–Hartwig / Sonogashira / Negishi）：机制上 = 加一条 profile +
  加参照记录，引擎零改动（profiles.py 的 PROFILES 表就是扩展点，演示这一页即可）。
  现在不放功能：没有参照记录的反应类型只会整屏 NO_COMPARABLE，暴露短板。
- **更多量纲**（ee、TON/TOF、选择性）：outcome_type 词表扩展即可，同样等参照集跟上。
- **重执行**（DFT / MD / 谱图解析 / OPTIMADE 联库）：不做——不是「有 AI 就行」，
  一天内接上的 DFT 是假的，评委问收敛参数即穿帮；轻执行（Track B）与重执行的分界线在此。

## 5 · 铁律不因拓展而破

①②③ 的任何输出都沿用同一套红线：判定来自引擎、引用只出证书、不判成败、
不跨口径给区间、`imported_unchecked` 的候选永远不直接进判定结论。
拓展是让更多人看到证书，不是让模型多说一句话。

## 7 · 答辩三句话（v2 新增弹药）

1. 「对方有六项执行能力，我们有六项判定对应物——批量工作流的判定版是整表审计，
   跨库比对的判定版是文献两两判定，机器学习的位置我们用能力边界矩阵诚实占位。」
2. 「扩展反应类型 = 加一条 profile + 加一条记录，引擎零改动；我们窄是参照集窄，不是架构窄。」
3. 「我们从不预测，但我们把『不能比』换算成了『补哪条最值』——这是对方不做的排序能力。」
4. 「对方的手接在开源公共库上（pymatgen/ASE/jobflow），我们的手也是（RDKit 化学感知、
   确定性统计）——差别在于：他的算力用来产出数据，我们的计算用来让每一次『能不能比』更准。」

## 8 · GitHub 公共库点子（第一轮调研，2026-10-30）

### 直接可借：ORD（github.com/open-reaction-database，JACS 2021，MIT/Relay 背书）

ORD 的三条设计恰好是我们三个维度论的**外部权威佐证**，答辩引用价值最高：

| ORD 原文做法 | 对应我们的 | 引用话术 |
|---|---|---|
| 把「yield 如何定量」做成结构化元数据，"使下游能区分真分离收率与 LCMS 峰面积估计" | 维度 3（口径） | 「2021 年 ORD 建库就把口径当一等公民——我们做的是它的判定化：不只标注，还拒绝跨口径并列」 |
| HTE 产率"可能未校准（相对紫外峰面积）"单独警告 | 校准维（calibrated/uncalibrated） | 「校准缺失不是小事，ORD 为此单独设警告——我们更进一步：未校准不进差值结论」 |
| 提交需人工审稿、与原文献逐条比对 | A_confirmed / imported_unchecked 分级 | 「我们的证据分级就是 ORD 的人工审稿环节，只是把结论写进了每张证书」 |

### 反面论据：ORDerly（github.com/open-reaction-database/orderly 的清洗管线）

其论文结论「盲信 ORD 数据标签导致条件预测准确率虚高」——是 evidence_grade 分级
必要性的现成实证：**未核验标签毒化数据集**，与我们"imported_unchecked 永不进结论"同源。

### 移植级点子（后续可做，不进本次提交）

- ORD 的 per-record 校验脚本（单位绑定、最小字段集）→ 可并入 input_audit 扩展项；
- ORD 的"数据集内同模板枚举"（一行变百行）→ 对应我们 audit-table 的批量输入形态，
  已由 `--audit-table` 支持其行数组格式。

### 其他公共库（已扫，结论）

- ChemDataExtractor2 / OSRA：重抽取路线，我们已有 extract.py 轻量层，不引入依赖；
- pymatgen/OPTIMADE：材料域，借「查询 provenance 随结果走」的理念（我们 locator 已做到）。

## 9 · 版本与交接注意

- 引擎版本随新命令升至 **chemcritic-engine/1.3.0**（提示词头部同步改）；
