## 1. 定位

**一句话：** 实验没做出来之后，告诉你下一个该做哪个实验的多智能体系统。

**它做的三件事：**

1. **定位**——你的结果落在哪个可比体系区间里（不是"正不正常"，而是"你属于哪一档，这一档的天花板是多少"）；
2. **推演**——若低于本档水平，并行推演候选机制，每个机制带文献证据、反证与可区分性；
3. **设计**——输出一棵序贯判别实验决策树，用最少的实验排除最多的机制，并给出条件迁移路径。

**不做什么：** 不做收率预测、不做实验控制、不宣称找到唯一真因、不做跨反应类别泛化。

## 3. Agent 规格

### A0 主控 Orchestrator

| 项 | 内容 |
|---|---|
| 职责 | 驱动六步状态机；判定缺字段并生成追问；处理中断/失败与降级；汇总各 Agent 输出为最终卡片 |
| 输入 | 用户实验记录（表单或自然语言）、各 Agent 返回结构 |
| 输出 | 会话状态、追问清单、最终复盘卡（定位 + 机制 + 实验计划） |
| 关键逻辑 | 必填字段缺失 → 不进入 A2，先追问；A1 无命中 → 进入"证据不足"分支而非报错；任一 Agent 超时 → 降级输出已完成部分并标注 |
| 失败处理 | 不做无证据推断；缺数据时输出 `NEEDS_EVIDENCE` + 追问 |
| 所需能力 | **SciencePal：Agent Co-Building（自建 Agent + 定制提示词 + 工具绑定）、Session/Share** |
| 外部软件 | Pydantic（schema 校验）、`transitions` 或手写状态机、Jinja2（卡片模板） |
| 数据 | 六步链定义、必填字段清单 |
| 人力技能 | 提示词工程、状态机设计 |

### A1 取证 Agent

| 项 | 内容 |
|---|---|
| 职责 | 从知识库检索同底物/近邻底物先例，抽成 **entry 级** 结构化记录（条件、结果、口径、locator） |
| 输入 | 底物对（SMILES）、反应类型、检索范围 |
| 输出 | `LiteratureEntry[]`，每条含 DOI、表/entry/页码、条件全字段、`outcome_type`、`assay`、`internal_standard`、证据等级 |
| 关键逻辑 | 抽不到的字段一律写 `UNKNOWN`，**禁止补猜**；`outcome_type` 无法确定时标 `unknown` 并降低可比性；识别"自动化取证"线索（原文是否提及内标/校准/定量方法） |
| 失败处理 | 无命中 → 返回空集 + 检索词记录，由 A0 走"证据不足"分支 |
| 所需能力 | **SciencePal：Personal Knowledge Base（上传 PDF、语义检索、会话内引用）、Sandbox（PDF 解析）、Subagent（批量核验）** |
| 外部软件 | PyMuPDF / pdfplumber（PDF 文本与表格）、`rdkit`（SMILES 规范化与子结构匹配，可选）、正则 |
| 数据 | 11 篇已下载 PDF（`outputs/2026-10-21-Suzuki文献包/PDF/`）、34 条候选池（`refs/pool.json`）、6 条 SM 记录 |
| 人力技能 | 化学文献抽取（能读懂表注与脚注）、英文原文定位 |

### A2 定位 Agent

| 项 | 内容 |
|---|---|
| 职责 | 对每条文献记录与用户实验做 8 维门槛判定 → 等价类划分 → 分档定位 → 异常判定与置信度 |
| 输入 | 用户 `ExperimentRecord` + `LiteratureEntry[]` |
| 输出 | `Certificate[]`（每条的判定与阻断维度）、`ComparisonBlock`（可并列块）、`BlockedPair[]`、`PlacementResult`（所在档、本档区间、与档内水平差、置信度） |
| 关键逻辑 | 4 条硬门槛（底物对 / 产物 / `outcome_type` / assay·校准）任一不过或 `UNKNOWN` → 禁止同框；4 条软门槛只降证据等级；分档按催化体系族（见 §5） |
| 失败处理 | 可比块为空 → 输出 `NO_COMPARABLE` + 解锁清单，不给出"正常/异常"结论 |
| 所需能力 | **SciencePal：Sandbox（确定性 Python 规则引擎，LLM 无权覆盖判定）、Skill（规则可打包导出）** |
| 外部软件 | 纯 Python + Pydantic；`pandas`（汇总与图表数据） |
| 数据 | 8 维门槛规则表、分档定义（**需化学角色签字**） |
| 人力技能 | 化学口径判断（什么算同口径）、规则形式化 |

### A3 机制 Agent

| 项 | 内容 |
|---|---|
| 职责 | 当结果低于本档水平时，并行推演候选机制；每个机制给出理由、文献证据、反证、可区分性 |
| 输入 | `PlacementResult` + 用户实验条件 + 文献记录 + 机制库 |
| 输出 | `Mechanism[]`（通常 3–6 个），每个含 `supporting_refs` / `counter_refs` / `discriminating_test_hint` / `prior_rank` |
| 关键逻辑 | **并行派子任务**（一个机制一个子 agent）：先检索该机制在同类体系的文献支持与反证，再判定是否适用于本例；无文献支撑的机制保留但标 `speculative` 并降到最低优先级 |
| 失败处理 | 机制全部无证据 → 输出"仅列出待验证可能，无文献支撑"，不排优先级 |
| 所需能力 | **SciencePal：Subagent（父级派生子 agent，最大 10 并发）、Knowledge Base（检索）、Memory（复用历史判读）** |
| 外部软件 | 无（LLM 推理为主）；可用 `rdkit` 辅助判断取代基电子效应 |
| 数据 | 机制库 v0（Suzuki 通用 8–10 条，含判别实验建议） |
| 人力技能 | 有机化学机理（Pd 催化循环、转金属化、碱/水的作用、催化剂失活路径） |

### A4 设计 Agent

| 项 | 内容 |
|---|---|
| 职责 | 把候选机制转成**序贯判别实验决策树**；计算实验参数（当量、浓度、物料衡算）；生成实验记录表与图；评估条件迁移可行性 |
| 输入 | `Mechanism[]` + 用户条件 + 目标（提收率 / 判断损失位置 / 换体系） |
| 输出 | `ExperimentPlan`：决策树（首验 → 分支 → 终止规则）、每个节点的操作步骤、观测指标、预期结果矩阵、成本（天/物料）、以及"该实验能排除哪些机制"的映射 |
| 关键逻辑 | 排序目标 = **单位成本排除机制数最大**；先跑最便宜的区分性实验；若某实验无法排除任何机制则剔除；迁移评估给出改动维度与预期，不承诺结果 |
| 失败处理 | 机制过少（≤1）→ 不出决策树，只出一条验证实验 |
| 所需能力 | **SciencePal：Sandbox（物料衡算、当量/浓度计算、matplotlib 出图、生成 CSV/表格）、Skill（实验设计模板）** |
| 外部软件 | `pandas`、`matplotlib`、`jinja2`（实验记录表模板） |
| 数据 | 判别实验知识库、物料与安全常识（不涉及具体采购） |
| 人力技能 | 实验设计、序贯决策、有机合成实操经验 |

### A5 记录 Agent

| 项 | 内容 |
|---|---|
| 职责 | 保存本轮实验、判定、机制与计划；用户回填后续结果后自动重算；生成复盘报告与组会/投稿用材料 |
| 输入 | 全链路输出 + 用户回填的新实验结果 |
| 输出 | 项目记忆条目、历史时间线、可分享报告 |
| 关键逻辑 | 每次回填触发 A2 重算（证书升级/降级）；保留每轮的模型版本与规则版本以便复现 |
| 失败处理 | 回填字段缺失 → 标记"不完整轮次"，不参与趋势判断 |
| 所需能力 | **SciencePal：Memory（跨会话记忆）、Share Link（只读分享）、通知/邮件提醒** |
| 外部软件 | SQLite 或 JSON 文件（本地备份用，可选）；`jinja2`（报告模板） |
| 数据 | 全部历史记录 |
| 人力技能 | 科研报告写作 |

## 5. 判定规则（8 维门槛 + 分档）

**硬门槛（任一不过或 UNKNOWN → 禁止同框）**

| # | 维度 | 判定 |
|---|---|---|
| 1 | 底物对一致 | 取代基与位置一致；芳基碘/氯、烯基/杂芳基默认排除 |
| 2 | 产物一致 | 目标产物结构一致 |
| 3 | 结果口径 `outcome_type` | isolated / GC / ¹H NMR / conversion 必须同类；**禁止换算与区间拼接** |
| 4 | Assay 与校准 | 内标种类、校准方式、以哪个底物为基准；未注明即 UNKNOWN |

**软门槛（只降证据等级，不阻断，但须标注）**

| # | 维度 |
|---|---|
| 5 | 规模 / 当量 / 浓度 |
| 6 | 催化体系（前体 + 配体 + mol%） |
| 7 | 碱 / 溶剂 / 温度 / 时间 / 气氛 |
| 8 | 后处理与纯化路径 |

**分档（Suzuki 首期，需化学角色签字）**

| 档 | 催化体系族 | 首批对应记录 |
|---|---|---|
| A 经典膦配体 Pd | Pd(PPh₃)₄ / Pd(OAc)₂+膦配体、碳酸盐或 NaOtBu、有机溶剂 | SM-001（40% isolated）、SM-003（95% NMR） |
| B 无配体/水相 Pd | PdCl₂ 无配体水相（含原位生成 Pd(0)） | SM-002（100% isolated） |
| C 负载 / 纳米颗粒 / 非膦配体 | MOF 固载、预先制备的 Pd NPs、pincer/NHC、机械化学 | SM-004（unknown）、SM-005（95% isolated，边界 B/C）、SM-006（GC） |

> 分档的意义：**"异常"只能在档内定义**。跨档比较只能作为"迁移目标"，不能作为"正常区间"。
> 判档由 `engine/tier.py` 从受控词表字段确定性计算，边界情形自动标记 `borderline` 并做双档敏感性分析。完整规则见 [`docs/rules/分档定义-待签字.md`](../rules/分档定义-待签字.md)。

## 6. 数据结构

```text
ExperimentRecord   实验输入（含 missing_fields 与 user_report_only 标记）
LiteratureEntry    文献 entry 级记录（conditions + outcome + locator + evidence_grade）
Certificate        8 维判定结果 + verdict + blocking_dimension + unlock_condition + peer_block
PlacementResult    所在档 / 本档区间 / 档内偏差 / 置信度 / 依据
Mechanism          机制 id / rationale / supporting_refs / counter_refs / discriminating_test / prior_rank
ExperimentPlan     决策树节点 / 操作步骤 / 观测指标 / 预期矩阵 / 成本 / 可排除机制集
```

**关键约束：** `Certificate` 与 `PlacementResult` 由规则引擎生成，LLM 只能解释、不能改写；`user_report` 与 `verified_characterization` 分字段存储（沿用 `docs/2026-10-21` 的 D1 决策）。

## 7. 评测设计

**指标**

- **FPR（假精确率）** = 系统允许并列但 gold 判 BLOCKED 的对数 ÷ 允许并列的对数
- **FNR（漏拒率）** = 系统阻断但 gold 判 COMPARABLE 的对数 ÷ 应可并列的对数
- **可比类覆盖率** = 某底物的最大等价类大小 ÷ 该底物报告值总数

**Gold set：** 12–15 对，从 6 条 SM + 34 条候选中选，标注 `PASS / BLOCKED + 阻断维度`。

**Baseline：** 同批文献直接问通用 LLM"该底物的收率范围是多少"→ 典型输出为跨口径的假区间。用于对比 FPR。

**科学结论（可写入 ≤5 页说明）：** 在本反应同一底物的 8 个报告值中，仅 3 个构成同一等价类（分离收率口径），其余必须隔离。

## 8. 风险与降级

| 风险 | 触发信号 | 降级动作 |
|---|---|---|
| 平台不支持自建 Agent 调沙箱 | 10/25 验证失败 | 门槛引擎改本地 Python 执行，结果回贴会话；在说明中如实披露 |
| Subagent 不可用 | A3 只能串行 | 机制推演改为单轮并行提示（一次让 LLM 输出 5 个机制 + 证据），标注"单轮" |
| Memory 不跨会话 | A5 失效 | 用会话内摘要 + 外部 JSON 存档，说明中标"未做跨会话记忆" |
| 抽取不稳 | 抽错 entry/脚注 | 只做 3 篇精确抽取 + 人工 spot-check；抽不出写 UNKNOWN |
| 工作量超期 | 10/28 未串通 | 按 P0 → P1 → P2 顺序砍（见分工文档 §5） |

## 9. 与评审维度的对应

| 评审维度 | 本方案的落点 |
|---|---|
| 科学价值 | 揭示文献数值的不可比性并可量化（覆盖率 + FPR）；输出"档内定位"而非伪阈值 |
| 创新性 | 数值输出空间受规则约束（机制而非提示词）；机制并行推演 + 序贯判别实验设计 |
| 可行性 | 6 步链可完整演示；知识库/沙箱/子 agent/分享链接全部为平台既有能力；含 baseline 对照 |
