## 3. 依赖关系（关键路径）

```text
A: 分档签字 + 8维口径 ──┐
                        ├──▶ C: 门槛引擎 ──▶ C: 六步链串通 ──▶ B: 评测 ──▶ 视频/说明
A/B: 40–50 条 entry 抽取 ┘                        ▲
                                                 │
C: 平台能力验证（10/25 上午，所有工作的前置）──────┘
```

**三条硬依赖（谁卡谁）：**

1. **C 的平台验证卡全部工作**——若沙箱或自建 Agent 不可用，A3/A4 方案要改，必须在 10/25 上午出结果。
2. **A 的分档与 8 维口径卡 C 的门槛引擎**——A 不签字，C 只能写占位逻辑。
3. **A/B 的 entry 抽取卡 B 的评测**——gold set 没有记录就无从标注。

**产能瓶颈：** 40–50 条 entry 的抽取是 6 天里最硬的活。**B 负责抽数值/条件/口径，A 负责审 locator 与可比性判断**，两人并行，不要都压在 A 身上。

## 4. 每日任务

> 每日固定动作：① 早 10 分钟站会（**A 主持**：昨日完成 / 今日交付 / 阻塞与责任人）；② 当日产出落盘到 `docs/` 或 `outputs/`，文件名带日期；③ 站会结束前更新本节的任务状态。

### 10/25（第 1 天）· 定口径 + 验平台 + 立评测基线

| 角色 | 任务 | 出口标准（可验收） |
|---|---|---|
| C | **平台四件套验证**（技术方案 §4.1 的 8 项打勾）；建知识库骨架，上传 3 篇核心 PDF | 8 项逐条有结论；不可用项当天告知 A/B 并确定降级路径 |
| C | 写 6 个 Agent 的提示词 v0（A0/A1/A2 优先） | 提示词落到 `docs/`，可被 A/B 阅读 |
| A | 主持站会、排定当日优先级；**平台验证不通过时拍板降级路径** | 当日优先级与降级决定记录 |
| A | **分档定义签字**（档 A/B/C 的催化体系族划分）；确认 SM-001 的 40% 归入档 A 分离类 | 一页签字稿；后续判定以此为准 |

| B | 定义 FPR / FNR / 覆盖率计算方式与 baseline 问法 | 公式与 baseline 提示词落盘 |
| B | 开始抽 entry（与 A 并行）：从 34 条候选中选 15 条 | 15 条抽到"条件 + 结果口径"级别 |

**今日检查点（A 主持）：** 若 C 的平台验证未通过 → 由 A 当场拍板：走"本地脚本 + 会话编排"降级，或砍掉依赖沙箱的 A4；决定写入 `docs/`。

## 7. 保命规则

1. **每天必须有一个能演示的东西**——不允许出现"两天在写代码但跑不起来"。
2. **化学结论只有 A 能签字**，C 不得自行撰写结论文案。
3. **规则引擎的判定 LLM 不得覆盖**——任何"让模型自己判断一下"的临时改动，等于放弃本项目最核心的创新点。
4. **抽不到就写 UNKNOWN**，任何补猜都会在评审追问时崩。
5. **10/28 之后不再加功能**，只修阻断演示的问题。
6. **会议决定**：范围变更、砍功能、是否提交，由 A 拍板并写入当日站会记录，避免反复推翻。
7. **A 同时是科学签字人与队长**——若某个科学判断会拖慢关键路径（例如继续追某条文献的 SI），由 A 自己决定"标注 UNKNOWN 先放过"，不要卡住 C。
