# ChemCritic 多反应类型扩展调研与 DSH 检索任务包

> 版本：2026-10-18  
> 用途：先筛选 ChemCritic 下一阶段值得扩展的反应类型，再由 DSH 按统一标准开展系统检索。  
> 当前产品边界：黑客松 MVP 仍以 Suzuki–Miyaura 芳基溴/芳基硼酸偶联为例；本任务不是把所有反应立即加入 MVP，也不是据少数论文声称 Agent 已覆盖广域化学知识。

## 1. 这次调研要回答什么

1. 哪些常见有机反应类型存在可检索、可引用、条件和结果较完整的文献或公开实验数据？
2. 哪些数据真正适合“实验结果复盘/条件比较”，而不仅是反应物到产物的专利反应记录？
3. 哪些类型适合作为 Suzuki 之后的首批扩展；每类的适用范围、数据偏差和证据缺口是什么？
4. 没有自有实验室时，哪些验证可以用公开文献/HTE 数据做，哪些结论必须等待真实实验？

调研目标是形成**有来源的反应类型选择依据和一批可复核案例**，不是先凑一个很大的文献数量。

## 2. 已有初步线索（供 DSH 核验，不视为最终结论）

| 反应类型 | 初步数据/文献线索 | 当前判断 | DSH 重点核验 |
|---|---|---|---|
| Suzuki–Miyaura 偶联 | 已有本项目同底物直接先例；公开 Suzuki HTE 数据曾用于产率预测，ORD 论文列出 5,760 条相关高通量记录 | 作为当前 MVP 基线；HTE 条件优化数据与文献实验条件不可混为一谈 | HTE 原始数据是否可下载、字段/产率口径、底物覆盖、许可；另收集文献案例并标明分离收率或分析产率 |
| Buchwald–Hartwig 胺化（C–N 偶联） | 文献报告过 3,955 条条件组合的 HTE 数据；Nature Chemistry 的反应 reactome 分析包含约 3,000 条 Buchwald–Hartwig 反应 | 强候选：有成组条件与正负结果线索；其数据仍可能集中在窄底物组合 | 原始数据及 SI 可用性、底物/配体/碱/添加剂字段、测定方法、重复实验、失败结果是否保留 |
| 酰胺偶联 / N-酰化 | 公开项目仓库声称提供约 47,000 条、95 种条件的 HTE 数据；另有文献数据集和 ORD 记录 | 强候选：数据规模线索突出；需确认原始公开来源、不同偶联剂分布和 assay 与分离收率的差异 | 核对论文与仓库是否一致、数据许可证、具体测定/校准方式、失败值、底物覆盖及同一底物配对条件 |
| Ullmann C–N 偶联 | 反应 reactome 研究涵盖 Ullmann 偶联 | 中等候选：有系统研究线索，数据可复用性尚待确认 | 精确反应定义、记录数、公开下载位置、反应条件/产率口径、与 Buchwald–Hartwig 区分规则 |
| 氢化（均相与非均相分开评估） | 反应 reactome 研究涵盖均相和非均相氢化 | 中等候选：实验结果可能丰富，但“氢化”过宽，底物、催化剂、压力及选择性指标差异大 | 不要作为一个单一类别合并；分别评估公开数据、气体压力/装置字段、转化率/选择性/分离收率口径 |
| Heck 偶联 | 本轮未确认与上述 HTE 数据同等级的公开成组数据 | 探索候选，先查数据可得性，再决定是否深挖 | 找方法学/优化论文、开放 SI/数据；不得因反应常见就假设有高质量结构化数据 |
| Sonogashira 偶联 | 本轮未确认可直接复用的成组 HTE 产率数据 | 探索候选 | 检查 Cu 助催化、胺碱、脱卤/均偶联副反应等关键字段及数据集可得性 |
| Negishi 偶联 | 有反应优化与数据驱动研究线索，但数据范围/公开性需核实 | 探索候选 | 核实有机锌试剂制备/滴定、无水惰性气氛、底物范围和可下载性；评估对普通用户输入的负担 |
| 还原胺化 | 常见药物化学转化，但本轮没有确认统一的可直接用于条件比较的公开数据集 | 探索候选 | 分开评估直接还原胺化与分步方案；注意底物组合、还原剂、催化氢化、选择性及分析口径 |

### 初步证据来源

- Open Reaction Database（ORD）原始论文，介绍可复用的反应数据结构，并列出 Suzuki 和 C–N 高通量示例：[The Open Reaction Database, JACS](https://pubs.acs.org/doi/10.1021/jacs.1c09820)。
- HTE 数据跨反应分析，包括 Suzuki、Buchwald–Hartwig、Ullmann、均相/非均相氢化及其数据范围限制：[Probing the chemical ‘reactome’ with high-throughput experimentation data, Nature Chemistry](https://www.nature.com/articles/s41557-023-01393-w)。
- 公开反应数据用于 yield prediction 的比较研究，讨论 Suzuki 和 Buchwald–Hartwig HTE 与较宽泛 ELN 数据之间的差异：[On the use of real-world datasets for reaction yield prediction](https://pmc.ncbi.nlm.nih.gov/articles/PMC10189898/)。
- 酰胺偶联 HTE 仓库及数据说明（包括 47k/95 conditions 声明；需 DSH 再对照论文和数据文件核验）：[AIChemEco amide coupling repository](https://github.com/aichemeco/amide_coupling)。
- 酰胺偶联 HTE 与不确定性/可行性研究：[Towards global reaction feasibility and robustness prediction with high throughput data and Bayesian deep learning, Nature Communications](https://www.nature.com/articles/s41467-025-59812-0)。
- ORD 中的 50,688 条 Pd/Ni/Cu 催化 C–N 偶联数据集记录（页面需要 JavaScript；检索时应尝试 ORD 导出/API 或公开数据文件）：[ORD dataset record](https://open-reaction-database.org/dataset/ord_dataset-805ad863feef48579d95d86a728035f4)。

> 以上是启动检索的候选线索，不等于已经逐篇或逐记录完成审计。所有数据量、开放性、字段完整度、许可证和收率测量口径均需 DSH 对原始来源复核。

## 3. 给 DSH 的工作拆分

### 阶段一：广度筛查

对上表 9 类逐类检索，优先级建议：

1. **优先深挖**：Suzuki、Buchwald–Hartwig、酰胺偶联。
2. **重点评估**：Ullmann C–N、均相氢化、非均相氢化。
3. **先做可得性筛查**：Heck、Sonogashira、Negishi、还原胺化。

每类至少检索：高质量综述或权威方法学文献、代表性原始研究、公开实验数据集/补充信息。若找不到可验证的成组数据，应如实记为“未发现/暂未核实”，不要用二手摘要补数。

### 阶段二：深度案例集

从证据可得性最好的 **4–6 类**进入深挖；每类尽量交付至少 **3 条可复核案例**，条件允许时覆盖：

- 高、中、低/失败结果，而非只挑成功高收率论文；
- 同一或高度相近底物的不同条件对照；
- 真实文献实验与 HTE 记录分开；
- 原始论文与 SI 的条件、产率记录相互核对。

若某类无法满足最低证据要求，降低优先级并记录阻塞原因，不以低质量网页凑足 3 条。

### 阶段三：扩展优先级评估

对每类按 1–5 分打分，并给分数依据：

| 维度 | 判断问题 |
|---|---|
| 来源可靠性 | 是否有同行评审原始文献、SI 或可信开放数据仓库？ |
| 数据可得性 | 是否能实际下载/访问记录，而不仅是论文摘要提到有数据？ |
| 条件完整度 | 催化剂/配体/添加剂/碱/溶剂/温度/时间/规模/气氛等关键字段覆盖如何？ |
| 结果可解释性 | 分离收率、NMR/GC/LC/LC-MS 转化或相对响应是否明确区分？ |
| 可比案例密度 | 是否有同底物或相近底物在不同条件下的可比实验？ |
| 失败样本覆盖 | 是否保留低收率/失败结果，还是只报道成功实验？ |
| 用户价值与安全性 | 条件是否能用于合理复盘建议；危险试剂/高压/强放热等是否要额外限制？ |
| 扩展成本 | 化学定义、字段抽取和评测是否能在团队能力与比赛周期内完成？ |

不得把分数加总后伪装成精确科学结论；报告排名时附不确定性和关键证据缺口。

## 4. 统一案例记录模板

每个案例一行或一个结构化对象，字段如下。原文没有披露的字段写 `unknown`；原文明示未使用/不存在才写 `absent`。

| 字段 | 要求 |
|---|---|
| case_id / reaction_class | 稳定 ID；反应类型及更细子类 |
| source_type | 原始论文实验 / SI / ORD 或其他 HTE 数据 / 专利 / 二手来源 |
| citation / DOI / URL | 完整题录、DOI、可直接打开的链接 |
| source_locator | 页码、表号、entry、SI 页面/步骤、数据集 ID 或行 ID |
| reactants / product | 名称、结构标识（SMILES/InChI 若有）；区分底物与试剂 |
| catalyst / loading / ligand | 催化剂及载量、配体及当量；未报告则 unknown |
| base / additive / reagent | 化学身份、当量/浓度、功能（若原文说明） |
| solvent / concentration / scale | 完整溶剂比例、总体积、浓度、反应规模 |
| temperature / time / atmosphere / pressure | 保留原单位和原文表达；氢化压力特别记录单位与装置信息 |
| workup / purification | 记录是否影响 isolated yield 的关键步骤（有披露才写） |
| outcome_value / outcome_type | 数字与类型分开：isolated yield、NMR yield、GC/LC yield、conversion、selectivity、conversion proxy 等 |
| assay / calibration | 检测方法、内标/校准、响应因子、定量方式；未报告则 unknown |
| replicate / uncertainty | 重复次数、均值/方差/误差；没有披露则 unknown |
| evidence_level | A：原始论文+SI/数据核验；B：可信原始论文但字段缺失；C：二手线索/仅摘要；C 不进入性能基准 |
| comparability | 与本反应类型/目标案例的相同点、不同点；不能只写“可比” |
| limitation / claim_boundary | 可以支持什么判断，不能支持什么结论；特别注明相关性不能推出因果 |
| access / license | 下载方式、公开限制/数据许可；未确认则标待核验 |

## 5. 质量控制和不可违反的规则

1. 先找原始论文、SI、公开数据仓库或官方数据库记录。搜索摘要只用于定位，不作为精确条件/收率的最终依据。
2. 每个数字必须能定位到具体原文位置或数据记录 ID。找不到就写“待核验”，不能按常识补齐。
3. 绝不把 HTE 的 UV/LC-MS 未校准响应、转化率或 NMR yield 改写成分离收率；按来源原术语记录。
4. 正结果、负结果和失败反应都要保留，不能只挑高收率论文。明确标注公开文献的发表偏倚。
5. 不把不同底物、不同规模、不同分析方法的产率直接平均或拼成“典型收率范围”。
6. 文献条件是已报告的一个实验，不是对新底物或用户实验的成功保证；单个案例不能证明变量的因果效果。
7. 数据库里的 reaction record 不一定等于独立实验；检查重复、重复测量、数据来源重叠和条件标准化。
8. 数据集许可证/使用限制需要核查，不能仅因可下载就假设可以再发布或用于训练。
9. 没有实验室时可以做文献案例验证、字段抽取评测和公开数据回放；不得声称完成了 ChemCritic 自有湿实验验证。
10. 报告结论必须区分“可支持文献检索与有据复盘”“可用于特定数据域内预测”“已证明可泛化到新反应/真实实验”这三种不同强度。

## 6. DSH 最终交付物

请交付以下文件/章节：

1. **反应类型可行性矩阵**：每类的可靠数据入口、可下载性、数据规模（仅核验后填写）、结果口径、关键缺口、评分、扩展优先级。
2. **文献与数据集来源表**：题录、DOI/URL、来源类型、具体定位、访问/许可状态、核验日期。
3. **结构化案例集**：用第 4 节模板，优先提供 4–6 类、每类至少 3 条可复核案例；无法达到时说明原因。
4. **数据质量与偏差分析**：测定方法差异、文献正结果偏倚、HTE 与宏量实验差异、底物覆盖、重复/来源重叠、缺失字段。
5. **建议扩展路线**：建议下一类进入产品的前置条件、最小可用案例数/评测集建议、应避免的产品承诺。
6. **未核实清单**：逐项列出查询过但没有证据闭环的数字、论文、数据字段或许可问题。

## 8. 角色A接手后的复核清单

- [ ] 抽查每类至少 1 条原始来源，确认 DSH 的条件和结果抄录与原文一致。
- [ ] 特别核对 HTE outcome 是 calibrated yield、uncalibrated response 还是转化率。
- [ ] 检查反应类型定义是否重叠（例如 Buchwald 与 Ullmann C–N），要求明确分类规则。
- [ ] 只把达到来源/字段/案例比较门槛的类型提报进入下一轮；其余保留为待验证候选。
- [ ] 把新类型的扩展决策和适用范围写入产品边界，不修改当前 MVP 基线，除非团队另行讨论决定。
