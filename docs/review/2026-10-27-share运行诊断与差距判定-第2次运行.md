## 三、仍存在的问题（按严重度排序）

### 🔴 问题 1：过程自述 + 答案重复，全部暴露在 share 回放里（观感致命）

25 条 assistant 可见消息中约 20 条是英文过程叙述，评委点开回放会看到一串调试日志：

- "I'll start by verifying the engine is ready…" / "The engine isn't at the expected path. Let me check the workspace structure." / "The engine isn't installed. I need to set it up first…"
- "**Engine is ready: 19 passed, 0 failed**. Now let me build the user's Record JSON…"
- "The engine expects a `record_id` field…" / "The engine output was truncated…"

且**第一层答案被完整输出了两遍**（消息 [111] 与 [117] 内容几乎相同），用户/评委看到两遍重复回答。

违反 v3：「写完『回复展开』必须立即停止」「禁止输出过程自述」。模型把"思考/草稿"当成 assistant 文本发了出去。

**改进：** ① 平台侧中间过程消息（tool-call 回合）content 必须为空，只携带 tool_calls；② 最终答案只允许在最后一条 assistant 消息交付；③ 用户可见文案禁止出现"引擎""测试通过""record_id""L1/L2"等词。

### 🟠 问题 2：L1/L2 内部判定术语泄漏进用户文案

第一层【为什么】里写了 "可并排比较(L1)" "未阻断(L2)" —— v3 用语规范明确 **L1、L2、D3 一律不出现**，应改说具体化学差异（"溶剂同为非含水体系"等）。属小修，但正是评委最容易被抓的细节。

### 🟠 问题 3：引擎/数据未预装，Agent 现场自探索（工程脆弱，浪费 ~15 次调用）

- 首次执行 `skills/chemcritic-comparability/scripts/chemcritic_engine.py` → **路径不存在**（说明 Skill 并未真正注册进平台 workspace）；
- Agent 随后：ls 探索 → git clone → 路径再错 ×1 → schema 错误（`record_id` 不合法）→ 改写 → 输出被 `head -80` 截断 → 重跑全量 → 再花 9 次调用去 pool15/pool30/引擎源码里翻 citation（中途还找错文件，以为在 pool15）。

演示回放里这是"现场装环境 + 反复试错"，且任何一步失败都可能让会话翻车。

**改进（写进给 C 的合并指令）：** ① 把 engine + data + SKILL.md 打包预装到平台 workspace **固定路径**，首次调用即命中；② bootstrap 只做"验证"不做"安装"；③ 引擎 `--json` 输出直接带 `citation` + `locator`（或输出引用映射表），Agent 无需回头翻数据文件。

### 🟡 问题 4：环境差异待确认

本次会话的工具面是 `execute_command / create_file / full_file_rewrite`（含代码沙箱），与第 1 次的 `search_skills / get_research_state` 不同——确认这是团队 SciencePal 账号的标准配置（若是，第 1 次的 21 次空检索问题不会再出现；若否，需统一演示环境）。
