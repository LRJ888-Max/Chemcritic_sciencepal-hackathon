## 二、v5 修复的实测确认（可以写进演示材料的部分）

1. **判定只来自引擎。** 每轮可见 `chemcritic_engine.py --json` 真实执行，最终数字（40%、低 5 个百分点）与证书 `delta_vs_min=-5` 一致；未出现口算判定。
2. **算术差合规。** v3 时代的「相差 5 个百分点」禁令在 v5 下改为允许（铁律 5），本轮说法始终绑定「目前只有这一条可比参照，不能据此判断好坏」，无区间、无「正常范围」。
3. **T3 替代路径已修。** v3 时代「思维链想到但不说」的问题消失：正式回答主动给出同口径 Miyaura 40% 对照。
4. **T4/T5 先追问后判定。** 用平台「询问」表单收集碱/规模/载量，不再硬答；v3 的「D1 硬阻断下仍建议补软维字段」无效建议消失。
5. **T6 质量提升。** 8 条记录数值/口径/locator 全对，并主动声明「Miyaura 66% 与 40% 同属一篇」「Molecules 两条同篇不得视为独立来源」；口径未决两条复述了「表头写 Yield (%)，脚注却写 total conversion … based on GC（内标十六烷）」。
6. **最终答案层用语干净。** 正式答案无 L1/L2/COMPARABLE/SM 编号/「无其他差异」，均有「回复“展开”」引导行（T1 因停在追问表单除外）。
7. **Token 大幅优化。** 常规轮 54–117K（v3 首跑 1.1M）；仅 T6 异常（见问题 4）。

## 三、仍需改进（按优先级，附证据）

### 🔴 P0-1 过程自述泄漏 + 答案重复交付（10-27 问题 1，未修复）

每一轮的消息流里都有大段思考过程直接暴露给用户，T1b 尤其典型：

- 英文自述："I'll start by bootstrapping…" / "Engine is ready. Now let me write the user.json…" / "Let me write the answer."
- 中文自述：「引擎已就绪。现在写入用户实验数据并调用引擎。」「让我写最终答案。注意用语规范，不用内部术语。」
- **提示词模板指令原文泄漏**：「【为什么】最多 3 条，每条 ≤20 字，来自 soft_flags:」「写完最后一行立即停止。」
- **`</think>` 标签本身渲染到界面**（T1b）
- 答案重复交付 2–3 遍（草稿 + 定稿同屏）
- 中间消息泄漏内部术语：SM-001b、COMPARABLE、soft_flags、delta_vs_min、tier A

违反 v5 输出纪律 1/2/3 全部三条。演示回放中评委仍会看到一串「自言自语」。
**建议：** ① 平台侧：中间轮次 content 置空、只留 tool_calls；若模型支持 reasoning 剥离，配置 `thinking` 不入消息流（`</think>` 泄漏说明这是 runtime 层可修的）；② 提示词侧：把「工具轮次零自然语言」提为系统级硬约束并给 2–3 个反例；③ 交付层：最终答案只允许最后一条消息。

### 🔴 P0-2 T7 口径假设复发（判定层违规）

用户只说「收了 35%」，未说明口径。v5 明令「用户没明说收率口径时，不得替他指定，一律写 unknown 并追问」。实际行为：直接写 `outcome_type: isolated` 跑引擎，最终回答「你的分离收率 35%……相差 5 个百分点」——与 v3 时代 T7 的失败同构。【下一步】还写了用户从未提供的「Na₂CO₃」。
对比：T1（碱缺失）和 T4/T5（多字段缺失）都正确先追问，**唯独口径字段被假设**。说明「收率定义 > 碱 > 载量」的追问优先级在「口径表述模糊（‘收了’‘收率’）」场景下没有被模型识别为缺失。
**建议：** ① 提示词给「收了 X%」「收率 X%」这类模糊表述加显式规则：凡未出现「分离/GC/核磁/转化」字样一律视为 unknown；② 引擎侧兜底：user.json 的 outcome_type 写 unknown 时引擎已返回 NEEDS_EVIDENCE，考虑在 Agent 写文件前加一步自检脚本（校验 outcome_type 非 unknown 才允许继续），把「不得假设」从纯提示约束变成程序断言。

### 🟠 P1-1 「两处措辞复述」规则执行不稳定（P4 修复部分失效）

T2 只说「定量依据在库里是 unknown」「口径没定下来」，未按 v5 用语规范复述「表头写 Yield (%)，脚注写 total conversion … based on GC」；同一段规则在 T6 中却被完整执行。同一天同一规则一轮做一轮不做。
**建议：** 把该规则从「用语规范」表移到【结论】生成步骤附近（口径未决条目被提及时强制触发），并给一个「未复述即不合格」的自检清单项。

### 🟠 P1-2 跨会话记忆污染判定输入

T3/T2 的用户输入只有底物对和收率，未给催化剂/碱/溶剂等条件。Agent 从账号级记忆把 T1 的条件（Pd(PPh₃)₄ 3 mol%、Na₂CO₃ 2 equiv、无水 THF、N₂）默默填进 user.json，并写进【下一步】的实验设计里，读起来像用户申报过的条件。违反 v5「缺失字段写 null，不要填默认值」，且使判定输入不可追溯——证书看似可复现，实际输入是拼装的。
**建议：** ① 提示词明确「记忆只能用于追问措辞，不得填入 user.json」；② user.json 增加 `inputs_source` 字段（user_stated / memory / unknown），证书输出该字段，演示时可自证输入来源。

### 🟠 P1-3 知识库查询路径低效（10-27 问题 3 延续）

T6 为列 8 条记录耗费 **383.5K tokens、11 步**：搜索技能×3（失败）→ 自举 → 引擎（无实测值时 reference 为空）→ `ls` → `grep` → `sed -n '1180,1600p'` 翻引擎源码找知识库定义。任何一步失败都会翻车，且观感是「现场翻代码」。
**建议：** 引擎增加 `--list-records` 模式（一次输出全部记录的 citation/locator/口径/tier），或 `--json` 在无实测值时也返回完整 reference 映射；同时把引擎+数据预装固定路径，砍掉自举的 clone 步骤。

### 🟡 P2-1 技能未注册（噪音级）

「记录技能结果 chemcritic-comparability」每次返回 `Skill unavailable. Use search_skills…`。不阻塞主流程（bootstrap 可用），但回放里又是一条失败记录。**建议：** 按 10-27 合并指令把 SKILL.md 注册进平台，或干脆去掉该记录调用。

### 🟡 P2-2 行为不确定性

T1 与 T1b 同输入：前者用表单追问碱，后者推理「用户已说没记，再追问无意义」后直接 unknown 跑引擎。两种行为都说得通，但演示与评测需要确定性。**建议：** 在提示词里写死决策树：「用户明说未记录 → 写 unknown 继续；用户未提及 → 追问」。

### 🟡 P2-3 引用语言混杂（观感级）

正式答案里整段英文引用（"Synth. Commun. 1981, 11, 513, Table II, p-MeOPhBr row, value in parentheses"）嵌入中文句子。「照抄证书」保证了可核验，但观感生硬。**建议：** 证书同时输出 `locator_zh`（如「表 II p-MeOPhBr 行括号值」），规则改为「citation 照抄、locator 可用中文版」。

## 四、平台层问题（非 Agent 提示词，需要创建者/平台处理）

1. **点「使用」不绑定自定义 Agent。** 从智能体页点 ChemCrtic 的「使用」，进入聊天后仍是「通用智能体」。本次实测第一轮即中招：General Agent 用联网检索回答 T1，输出「不正常」「预期提升到 80% 以上」，并从共享记忆搬出 SM-001b、COMPARABLE、L2 等内部术语——若评委踩坑，观感是灾难性的。
2. **@提及必须下拉插入，纯文本 @ 无效；且自定义 Agent 需输入过滤词才出现在列表里。** 学习成本高，演示前应对评委给出明确的操作指引（或修复「使用」按钮的绑定逻辑）。
3. **工具面板全量暴露引擎 JSON**（含 SM 编号、verdict 内部值）。作为「运行详情」透明度是加分项，但需确认评委视角下它的定位是「可展开的审计证据」而非主消息流。
