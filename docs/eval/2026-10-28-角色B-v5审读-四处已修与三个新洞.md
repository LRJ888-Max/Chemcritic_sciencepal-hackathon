## 一、一句话结论

**措辞层的四处（P2/P3/P4/P6）确实修好了，P5 的跨档差值也修好了。但新写了一节「引擎接口契约」，其中两条字段引擎里根本不存在；同时把 T4 从"通过"推向"失败"——因为契约要求模型无条件相信 `placement.delta_vs_min`，而它在换底物的场景下会返回 0。**

不改这两处，跑 T4 会比 v3 更差。

## 三、三个新洞（按严重度）

### 洞 1｜`placement` 不看 `verdicts`，换底物也照样给差值 —— **会让 T4 从"通过"变"失败"**

实测（3-溴噻吩 + 苯硼酸，40% isolated，即 T4 用例）：

```
verdicts:  全部 BLOCKED，blocking_dimension = substrate
placement: status=PLACED, tier=A, reference_values=[40], delta_vs_min=0
```

**引擎一边说"底物不同，全部阻断"，一边说"你的 40% 与参照 40% 相差 0 个百分点"。**

根因在 `engine/placement.py:117`：

```python
same_class = [r for r in records if r.outcome_type == user.outcome_type]
                                        # ↑ 只按收率口径过滤，完全不看底物/产物/assay 判了什么
```

v3 时 T4 之所以"通过"，是因为模型自己从 `verdicts` 里读出了"全部 BLOCKED"，然后拒绝比较——**它绕过了引擎的错，救了一次**。

而 v5 行 115 恰好把这个自救路径堵死了：

> 差值取 `placement.delta_vs_min`（同档且你有实测值时才非 null），**不要自己相减**

行 59 又写：

> `placement.delta_vs_min` → **仅为 null 时：不许说任何差值**

T4 的 `delta_vs_min = 0`，非 null。按契约它必须说"相差 0 个百分点"。

**这是本次审读发现的唯一"必然翻车"项。** 演示时评委让你现场试一个新底物，就会看到这个。

**修法（C）**：`placement` 只统计 `verdict == COMPARABLE` 的参照。

```python
# engine/placement.py
def placement(user: Record, records: List[Record], verdicts=None) -> Dict[str, Any]:
    ...
    comparable_ids = ({v.reference_id for v in verdicts if v.verdict == "COMPARABLE"}
                      if verdicts is not None else None)

    same_class_all = [r for r in records if r.outcome_type == user.outcome_type]
    same_class = ([r for r in same_class_all if r.record_id in comparable_ids]
                  if comparable_ids is not None else same_class_all)

    if not same_class and same_class_all:
        # 同口径有参照，但底物/产物/assay 不可比 —— 必须说清是"不可比"，不是"没有"
        return {
            "status": "NO_COMPARABLE",
            "reason": "同口径（{}）的参照存在，但底物或产物不同，不能并排比较".format(user.outcome_type),
            "blocking_dimension": <取第一条 BLOCKED 的 blocking_dimension>,
            "candidates": [r.record_id for r in same_class_all],
            "action": "换回原底物，或为该底物补充同口径文献",
        }
```

调用处（`chemcritic_engine.py:1697` 与 `1703`）传 `verdicts` 进去。

同时把 `user.json` 里 `label_raw` 为空时的判定也接上（见洞 1b）。

**洞 1b（同一根因，5 行）**：实测 `outcome_type=isolated` + `label_raw=null` 时，
`verdicts` 全部 `NEEDS_EVIDENCE`（C 加的 P5b 生效了），但 `placement` 仍然 `PLACED / delta=-5`。
一份证书里一半说"需取证"、一半说"低 5 个百分点"。`placement` 应同样判 `UNDEFINED`。

### 洞 2｜`user.json` 示例是填满的 —— T7 的缺陷被写进了范例

v5 行 94–104 给的骨架是这样的：

```json
"outcome":{"value":35,"outcome_type":"isolated","label_raw":"分离收率"},
"conditions":{"catalyst":"Pd(PPh3)4","catalyst_mol_pct":3.0,"base":"Na2CO3","base_eq":2.0,
               "solvent":"THF","temp_c":60,"time_h":12,"atmosphere":"N2","scale_mmol":1.0,
               "equivalents":{"aryl_halide":1.0,"boronic_acid":1.2}},
```

而行 89 说"用户没明说收率口径时…一律写 unknown 并追问"，行 92 说"缺失字段写 null，不要填默认值"。

**模板和规则打架，模板赢**——模型要产出一个 JSON，最快的路径是改数字、不改结构。

我把两份都跑了引擎：

| 输入 | placement | soft_flags 里的差异 |
|---|---|---|
| **照抄模板**（碱 Na₂CO₃ 2 eq、载量 3 mol%、N₂、1 mmol、当量 1.0/1.2） | `PLACED / [40] / delta=-5` | 碱不同：na2co3 vs k2co3；载量相差 6.0 倍；气氛不同：n2 vs air；硼酸当量比相差 0.3 |
| **如实留 null**（只填用户真说过的） | `UNDEFINED` | 碱未记录；mol% 缺失；气氛不同：None vs n2 |

差别不是措辞，是**从"不能判定"翻成"可比、低 5 个百分点"，外加四条凭空生成的差异**。

更糟的是它绕过了 C 刚加的 P5b 防线——那条防线要求"用户侧口径必须有 `label_raw` 支撑"，而模板直接把 `label_raw` 写成了"分离收率"。

**对 T1 的具体后果**：现在（v3）T1 会说"碱未记录"，这是对的。换上 v5 这版，它很可能说"碱不同：Na₂CO₃ vs K₂CO₃"——**替用户指定了一种他从没提过的碱**。比现在更糟，而且是演示必出的那一屏。

**改法（A）**，把行 92–106 整段替换为：

```text
写成 /workspace/user.json：键必须齐全，值只能来自用户原话，其余一律 null。

{"record_id":"USER-001",
 "outcome":{"value":null,"outcome_type":null,"label_raw":null},
 "substrate":{"aryl_halide":null,"boronic_acid":null,"product":null},
 "conditions":{"catalyst":null,"catalyst_mol_pct":null,"ligand":null,"base":null,"base_eq":null,
               "solvent":null,"temp_c":null,"time_h":null,"atmosphere":null,"scale_mmol":null,
               "equivalents":{"aryl_halide":null,"boronic_acid":null}},
 "assay":{"method":null,"internal_standard":null,"quantification_basis":null},
 "catalytic_profile":{"catalyst_form":null,"ligand_family":null,"support":null,
                      "medium":null,"activation_mode":null}}

允许填值的唯一条件（拿用户原话逐字核）：
· outcome.label_raw ← 用户原话片段，逐字照抄。例："收了35%"就写"收了35%"，
                      不得改写成"分离收率"；只有用户说了"分离收率35%"才写"分离收率35%"。
· outcome.outcome_type ← 仅当原话里出现这些词：
    "分离/柱层析/称重/isolated" → isolated　　"GC/气相/内标" → gc
    "核磁/NMR" → nmr　　　　　　　　　　　"转化率/conversion" → conversion
    都没有 → unknown，并追问收率口径（见第一步）。
· conditions.* ← 用户明说了才填，没说就是 null。
    "THF" 不等于 "无水 THF"；没提碱就 null，没提载量就 null，没提气氛就 null。
    ★ 严禁把本示例里出现过的 Na2CO3 / 2.0 / 3.0 / N2 / 1.0 / 1.2 当默认值填进去。
```

一个字都不许省。这份模板是 T7 会不会再犯的唯一开关。

### 洞 3｜【结论】只有 happy path，缺"判不了"的分支

行 122 要求【结论】必须写"与哪篇的哪个值可并排比较、相差几个百分点"。

但 `placement.status` 可能是 `UNDEFINED`（口径未决）、`NO_CALIBRATED_REFERENCE`（T5 就是）、`TIER_UNKNOWN`、`NO_OBSERVED_VALUE`。这几种情况下 `delta_vs_min` 全是 `null`，行 59 又禁止说差值。

**两条规则对撞，模型只能二选一：要么编一个差值，要么吐一个残缺的【结论】。**

实测 T5（溴苯 90% GC）：`placement.status = NO_CALIBRATED_REFERENCE`，`delta = null`。它现在只能靠自己发挥。

**改法（A）**，行 122 后插一行：

```text
★ 先看 placement.status：只有 PLACED 才写"相差几个百分点"。
  非 PLACED 时，【结论】改写为一句："暂不能给出可比结论——" + 照抄 verdicts 里第一条
  blocking_dimension 对应的 unlock_condition（改写成化学说法，不出现字段名）。
  此时【结论】不许出现任何数字差。
```

## 五、还有一件事：T4/T5 的产品价值仍然为零

T4 上次判"通过"，是因为它没编。但产品上它什么也没给：用户问"正常吗"，得到"不能比"，然后没了。

v5 没有补这一块。`migration_targets` 只覆盖"同底物跨档"，覆盖不了"换底物"。

建议在行 116 后补一句（与 `kb/L3-gates.md` 的"可比替代项"对齐）：

```text
★ 0 条可比参照时，除了说"没有可比的参照值"，必须再给一条：
  "库内与你这类底物最接近的是 ___（作者 年份 卷页 表号），它做 ___%，口径 ___"；
  库内连近邻都没有，明说"本次检索 N 条记录，同底物 0 条"。
  只拒绝、不给出路，算不合格输出。
```

## 附：本次审读撤回的一条旧判断

我上一轮说"提示词少写了约束"。这一轮看完 v5 更确信：**问题不在写少，而在写反与写多**——
写反的是用语表（R1），写多的是示例（洞 2、R4）。

v5 新增的"引擎接口契约"这一节方向是对的，比 v3 让模型猜字段强得多；问题只是**契约比引擎超前了两项**。
建议以后改契约时，先在本机 `grep` 一遍字段名，确认引擎真的返回，再写进提示词。
